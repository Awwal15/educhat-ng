# Personalized Study Tips per Subject

## What we're building
When a student opens a subject chat, a "Study Tip" card appears at the top showing practical advice based on the topics where most WAEC/NECO candidates lose marks in that subject (e.g. for Mathematics: word problems, quadratic factorization; for Chemistry: mole concept, electrolysis).

To keep it fast on 2G networks, the tip is generated by AI **once per subject** and saved in the database — every student after that gets the stored tip instantly, with no AI wait.

## How it works

```text
Student taps subject
        |
        v
Chat opens + tip card loads
        |
   Tip already in database? ----yes----> show instantly (fast, 2G-friendly)
        | no
        v
  AI generates tip (one time) --> save to database --> show
```

## Changes

**1. Database — new `study_tips` table (Lovable Cloud)**
- Columns: `subject_id`, `subject_name`, `tip` (text), `updated_at`
- Public read access (tips are the same for everyone), write access only via the backend function
- One row per subject (9 subjects max — tiny, fast table)

**2. New edge function `get-study-tip`**
- Looks up the subject's tip in `study_tips`; if found, returns it immediately
- If missing, calls the AI (same fast model as chat) with a prompt listing common WAEC/NECO weak areas for that subject, saves the result, and returns it
- Tip content: 3–4 short bullet points — the weak topics, why students fail them, and one concrete study strategy; max ~100 words; ₦ rules and Nigerian context apply

**3. Chat screen — tip card (`src/components/LearningChat.tsx`)**
- Gold-accented "Study Tip" card with a lightbulb icon, shown at the top of the chat when a subject opens
- Collapsible: student can tap to expand/collapse so it doesn't eat chat space on small phones
- Dismiss button (X) hides it for that session
- Shows a subtle loading state while the first-ever generation runs

## Why cached instead of fresh every time
- Students on 2G would otherwise wait 5–15 seconds for AI each time they open a subject
- Weak areas per subject don't change per student — one good tip per subject serves everyone
- Saves AI credits: 9 generations total instead of one per student per visit

## Technical notes
- Reuses the existing AI gateway pattern from `learn-chat` (same model, small max_tokens)
- Follows the low-bandwidth rules: plain CSS, no new dependencies, tiny payload
- A refresh option can be added later (e.g. regenerate tips per WAEC exam year) — out of scope for now
